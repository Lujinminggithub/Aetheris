# Aetheris 平台共享知识与全局智能查询设计

**日期：** 2026-09-20
**状态：** 已确认，待实施计划
**范围：** Windows Core、Go Server、PostgreSQL、Qdrant、Model Gateway、Admin Web
**关联文档：** `2026-09-16-process-knowledge-rag-design.md`

## 1. 文档关系

本文扩展既有“过程知识层 + 通用模型补全 + 已验证结果纠错”方案，并替代关联文档中以下设计：

- 智能查询默认选择单一逻辑项目。
- 跨项目查询必须由用户显式选择“全部项目”。
- 知识索引以逻辑项目作为主要检索边界。

本文不取消原始事件、清洗事实、逻辑项目归属及租户隔离。项目和租户仍是证据追溯、权限控制、撤回和审计所必需的来源维度，但不再作为普通智能查询的默认知识分区。

## 2. 背景与问题

当前过程知识主要从 `ai.message` 和 `ai.tool_call` 中提取，能够识别人工问题、AI 最终回答和部分 Shell 工具调用，但存在以下缺口：

1. AI 发起的网页搜索、文档搜索、代码搜索及其返回结果没有形成完整的结构化证据链。
2. AI 明确输出的分析摘要与最终回答没有稳定区分，工具结果虽然在服务端类型中有定义，但采集和入库并不完整。
3. 知识单元、知识分块和 Qdrant payload 仍以 `logical_project_id` 作为主要检索范围，跨项目知识需要用户主动选择。
4. 相同知识在不同项目和不同租户之间重复存在，无法形成规范化的公共知识。
5. 直接取消 `tenant_id` 过滤会暴露其他租户的项目、设备、人员、路径、代码和原始对话，不满足隔离要求。
6. AI 搜索结果和 AI 自身生成的结论可能存在错误，不能未经验证就传播给所有租户。

因此需要建立“租户私有过程知识 + 平台公共知识”的双层架构，并将智能查询改为默认汇总当前租户全部项目知识和平台公共知识。

## 3. 已确认原则

### 3.1 全局知识边界

- 当前租户全部项目的知识默认参与智能查询。
- 所有租户可以共享经过脱敏、抽象、验证和平台认证的公共知识。
- 不跨租户共享原始对话、项目名称、设备、人员、路径、代码、工具原始输出和私有证据全文。
- 公共知识保留后台来源关系，但普通租户不能反查其他租户的原始证据。
- 项目归属从“检索分区”调整为“内部证据元数据”。

### 3.2 AI 过程采集边界

可以采集和吸收以下可观察内容：

- AI 发起的搜索词和检索范围。
- 搜索结果的标题、来源、时间、安全摘要和内容哈希。
- AI 发起的工具调用及脱敏后的工具结果。
- AI 明确输出的分析摘要、方案比较和最终结论。
- 人工追问、约束、确认、否定以及后续验证结果。

不采集模型未输出的隐藏推理过程，不把隐藏思维链作为产品能力或数据要求。

### 3.3 知识可信边界

- 单次 AI 回答、单条搜索结果或同一来源的重复内容只能形成候选知识。
- 已验证本地结果优先于人工确认、AI 结论和通用模型知识。
- 人工确认、证据验证或跨租户独立印证只能使知识进入待认证队列，不能直接向所有租户发布。
- 所有公共知识在发布前必须经过平台认证。
- 知识可信度使用可解释的状态和证据，不生成黑盒总分。

## 4. 目标

1. 补齐 AI 搜索、工具结果和显式分析摘要的采集与关联。
2. 从研发人员与 AI 的完整协作过程中提取可复用知识。
3. 默认汇总当前租户全部项目知识，不要求用户选择项目。
4. 将多个租户中可安全共享的结论规范化为平台公共知识。
5. 为公共知识提供确认、验证、认证、暂停、撤回和审计入口。
6. 智能查询同时使用当前租户私有知识、平台公共知识和通用模型补全。
7. 保证其他租户的身份、项目和原始过程数据不会通过查询或引用泄漏。
8. 保持事件不可变、知识可重建、索引可回滚、来源可撤回。

## 5. 非目标

- 不允许租户直接浏览其他租户的原始事件、会话或私有知识。
- 不将所有采集到的 AI 内容自动发布为公共知识。
- 不采集模型隐藏推理过程。
- 不保存外部网页全文作为公共知识正文。
- 不用同一 AI 回答的重复传播冒充跨租户独立验证。
- 不取消逻辑项目归属和私有知识中的 `tenant_id`。
- 不在事件上传请求中同步执行 Ollama 抽取、脱敏或知识合并。
- 不进行员工排名、绩效评分或个人能力评分。

## 6. 总体架构

```text
Windows Core
  AI 消息 / 搜索 / 工具调用 / 工具结果 / 显式分析摘要
                           |
                           v
events（租户私有、不可变）
                           |
                           v
clean_event_facts + process_sessions + process_turns
                           |
                           v
租户私有过程知识（保留租户、项目、设备、会话和证据）
                           |
              Public Knowledge Candidate Builder
                           |
       二次脱敏 -> 抽象 -> 去重 -> 冲突检测 -> 审核
                           |
                           v
平台公共知识（仅规范结论、适用条件、限制和匿名来源统计）

智能查询：当前租户全部私有知识 + 已发布公共知识 + 通用模型补全
```

租户私有过程知识是公共知识的来源，但公共知识不是原始过程数据的副本。两者使用独立的数据表、权限和向量集合。

## 7. 客户端事件合同

### 7.1 新增事件类型

#### `ai.search_query`

保存：

- `ai_tool`
- `search_provider`
- `search_kind`：web、documentation、code、workspace 或 knowledge
- `safe_query`
- `session_id`
- `message_id`
- `call_id`
- `project`，仅用于私有证据归属
- 原始时间和采集来源

#### `ai.search_result`

保存：

- `call_id`
- `result_index`
- `safe_title`
- `source_url`，经过凭据、查询参数和内部地址处理
- `source_domain`
- `safe_summary`
- `content_hash`
- `retrieved_at`

不保存网页全文。受版权、登录态或内部访问控制保护的内容只能保存最小摘要和来源标识。

#### `ai.tool_result`

保存：

- `tool_name`
- `tool_kind`
- `call_id`
- `result_state`
- `safe_summary`
- `result_hash`
- `session_id`
- `message_id`
- 原始时间

Shell 命令继续只保存命令类型、安全摘要和设备内 HMAC，不在工具结果中恢复完整命令。

#### `ai.reasoning_summary`

只保存 AI 明确输出给用户或明确写入结构化日志的分析摘要，包含：

- `safe_content`
- `summary_kind`：analysis、comparison、plan 或 reflection
- `session_id`
- `message_id`
- 原始时间

### 7.2 关联规则

关联顺序为：

1. `session_id + message_id + call_id`。
2. 父子消息关系或工具调用 ID。
3. 同设备、同私有项目、同 AI 工具和有界时间窗口。
4. 无法可靠关联时保留孤立证据，不强行组成结论。

### 7.3 适配器兼容

- Codex、Claude Code、Cursor 分别使用独立解析器。
- 只解析已识别的结构化记录，不对未知 JSON 字段做内容猜测。
- 未识别格式记录适配器健康告警、格式指纹和安全计数。
- 检查点必须在事件成功进入本地持久队列后推进，避免解析失败造成永久漏采。

## 8. 私有过程知识

现有 `process_sessions`、`process_turns`、`process_knowledge_units`、`process_knowledge_evidence` 和 `process_knowledge_chunks` 继续作为租户私有知识层。

需要扩展：

- `process_turns.statement_kind` 增加 search_query、search_result、reasoning_summary。
- `process_knowledge_evidence.evidence_kind` 增加 search、external_source、tool_result 和 analysis。
- 知识抽取器识别问题、搜索、分析、工具验证、最终回答、人工确认和后续否定的完整关系。
- AI 搜索和分析可以支持 rationale、alternatives、applicability 和 caveats，但不能在没有结论或验证的情况下伪装成已验证事实。
- 私有知识仍保存 `tenant_id`、`logical_project_id`、`session_id` 和原始证据 ID。

私有知识可以处于 unverified、partially_verified、verified 或 contradicted 状态。未验证知识可以参与当前租户查询，但排序低于已验证知识，并必须标明来源状态。

## 9. 平台公共知识模型

### 9.1 `public_knowledge_units`

保存平台级稳定知识标识和当前发布状态：

- `public_knowledge_id`
- `canonical_topic`
- `knowledge_type`
- `publication_state`：candidate、pending_review、published、suspended、withdrawn
- `current_revision`
- `created_at`、`updated_at`

### 9.2 `public_knowledge_revisions`

保存每个版本的安全内容：

- `public_knowledge_id`、`revision`
- `problem_pattern`
- `conclusion`
- `rationale`
- `applicability`
- `caveats`
- `alternatives`
- `validation_state`：unverified、source_confirmed、evidence_verified、cross_tenant_corroborated、platform_certified、contradicted
- `source_tenant_count`
- `independent_session_count`
- `canonical_hash`
- `extractor_version`、`redaction_version`、`review_policy_version`

公共正文不能包含租户、项目、设备、用户、路径、私有域名、代码正文或原始会话标识。

### 9.3 `public_knowledge_sources`

该表是受限的内部溯源桥，保存：

- 公共知识及 revision。
- 来源 `tenant_id`。
- 私有 `knowledge_id` 及 revision。
- 来源关系：supports、contradicts、supersedes 或 context。
- 独立性分组标识。
- 脱敏检查结果。

普通租户 API、公共知识详情 API 和 Qdrant payload 均不得返回来源租户或私有知识 ID。

### 9.4 审核、冲突和任务

- `public_knowledge_reviews` 保存确认、验证、认证、驳回、暂停、撤回、操作者、理由和时间。
- `public_knowledge_conflicts` 保存冲突结论、适用条件差异和处理状态。
- `public_knowledge_jobs` 保存生成候选、脱敏、合并、索引、撤回和重建任务。

### 9.5 权限

新增权限：

- `knowledge:confirm_source`
- `knowledge:verify`
- `knowledge:certify_public`
- `knowledge:withdraw_public`
- `knowledge:diagnose`

来源确认、技术验证和平台认证分别记录。首版不强制由两个不同账号操作，但数据模型保留后续启用双人审核的能力。

## 10. 公共知识晋升流程

### 10.1 候选生成

以下私有知识可以生成公共候选：

- 有测试、构建、运行结果支持的已验证结论。
- 人工明确确认且没有后续否定的设计结论。
- 两个以上独立租户产生语义相同、适用条件兼容的结论。
- 有可靠外部来源支持且已经完成安全摘要的知识。

以下内容不得生成可发布候选：

- 单次 AI 回答或单条搜索结果。
- 只有人工问题、没有回答的内容。
- 被否定、已冲突或来源已撤回的内容。
- 包含无法可靠脱敏的代码、路径、身份或内部系统信息。
- 动态 automation、命令残片和清洗层明确排除的数据。

### 10.2 独立性判断

跨租户印证必须排除：

- 同一 AI 回答被复制到不同项目或租户。
- 同一个外部网页摘要被多个租户重复引用。
- 同一设备、账号或导入批次产生的镜像数据。
- 仅文本相同但适用条件互相冲突的结论。

独立性按来源租户、会话、内容哈希、外部来源和时间关系综合判断，结果必须可解释。

### 10.3 发布门槛

自动流程只负责：

- 二次脱敏。
- 抽象和规范化。
- 相似知识聚类。
- 重复来源识别。
- 冲突发现。
- 生成待审核版本。

所有公共知识在进入所有租户可见的公共索引前，必须完成平台认证。平台认证记录审核人、审核依据、适用条件、版本和策略版本。

## 11. 知识治理页面

Admin Web 新增独立“知识治理”入口，包含：

- 待来源方确认。
- 待证据验证。
- 跨租户印证候选。
- 待平台认证。
- 已发布公共知识。
- 冲突、暂停和撤回项。

知识详情展示：

- 准备发布或已经发布的安全结论。
- 适用条件、限制、反例和冲突。
- 验证方式和验证结果。
- 匿名来源覆盖数，例如“3 个租户、7 个独立会话”。
- 当前租户自己的证据详情。
- 其他租户仅显示匿名统计。
- 修订历史、审核意见和操作日志。

允许的操作：确认、验证、认证、驳回、要求修改、暂停、撤回和重新发布。

## 12. 双 Qdrant 集合

### 12.1 私有知识集合

继续保存租户私有知识向量，过滤字段至少包含：

- `tenant_id`
- `logical_project_id`
- `knowledge_id`
- `chunk_id`
- `topic`
- `validation_state`
- `knowledge_version`

普通智能查询只使用 `tenant_id` 作为硬权限过滤，不使用项目作为默认限制。

### 12.2 公共知识集合

新增独立公共集合，仅保存已认证和已发布的 revision：

- `public_knowledge_id`
- `revision`
- `chunk_id`
- `canonical_topic`
- `knowledge_type`
- `validation_state`
- `publication_version`

公共 payload 不包含来源租户、项目、设备、人员、私有知识 ID和原始事件 ID。

### 12.3 一致性

PostgreSQL 是知识状态和正文的唯一事实来源。公共知识只有在 PostgreSQL revision 已认证且 Qdrant 写入成功后才进入查询视图。撤回时先令 PostgreSQL 查询视图失效，再异步删除向量。

## 13. 全局检索

### 13.1 默认范围

智能查询默认检索：

1. 当前租户全部项目的私有过程知识。
2. 平台已发布公共知识。
3. 必要时由通用模型补充知识缺口。

普通查询不要求项目、设备或日期。项目筛选仅保留在证据诊断和管理页面。用户明确询问历史时间点时，日期用于选择当时有效的知识 revision，而不是简单过滤事件时间。

### 13.2 检索流程

1. 识别问题意图、关键实体、精确术语和所需子主题。
2. 并行检索私有知识集合和公共知识集合。
3. 每个集合并行执行向量检索和关键词检索。
4. 按规范知识标识、内容哈希和语义相似度去重。
5. 检测私有知识与公共知识之间的冲突和适用条件差异。
6. 按主题、来源项目、来源会话和公共知识设置配额。
7. 生成逐结论证据计划，再交给模型生成答案。

### 13.3 排序优先级

1. 当前租户且环境匹配的已验证结果。
2. 平台认证且适用条件匹配的公共知识。
3. 当前租户人工确认的过程结论。
4. 当前租户未验证的 AI 分析、搜索和工具结果。
5. 通用模型知识补全。

数据量大的项目或租户不能占满全部上下文。相同知识只保留一个规范结论，但可以增加匿名覆盖统计。

## 14. 回答生成契约

- 回答按用户问题组织，不按项目逐项汇报。
- 多个项目中的相同结论合并为一个通用结论。
- 不同项目中的差异按操作系统、版本、技术栈和验证环境说明适用条件。
- 已验证私有结果可以纠正公共知识，但不能静默覆盖公共知识；系统同时创建冲突审核项。
- 通用模型补充内容必须标记为模型通用知识，不能伪装成私有或公共证据。
- 每个重要结论必须引用私有知识 ID、公共知识 ID 或明确标记为模型通用知识。
- 用户只能展开本租户原始证据。
- 公共知识详情只显示安全正文、适用条件、验证方式、认证信息和匿名来源统计。
- 没有充分本地或公共证据时允许回答，但必须降低置信度并说明知识来源。

## 15. API 设计

### 15.1 智能查询

现有异步查询接口保持兼容。新请求默认：

```json
{
  "question": "如何在 Windows 上实现 DLP？",
  "knowledge_scope": "tenant_and_public"
}
```

旧客户端传入项目、设备或日期字段时服务端继续接受，但普通全局查询不再把项目作为强制过滤条件。需要证据诊断时使用独立管理接口。

引用增加：

- `source_scope`：tenant_private、platform_public 或 model_general
- `knowledge_id` 或 `public_knowledge_id`
- `revision`
- `validation_state`
- `applicability`
- `anonymous_source_tenant_count`

### 15.2 知识治理

新增管理接口：

- `GET /api/v1/admin/public-knowledge/summary`
- `GET /api/v1/admin/public-knowledge/units`
- `GET /api/v1/admin/public-knowledge/units/{id}`
- `POST /api/v1/admin/public-knowledge/units/{id}/confirm`
- `POST /api/v1/admin/public-knowledge/units/{id}/verify`
- `POST /api/v1/admin/public-knowledge/units/{id}/certify`
- `POST /api/v1/admin/public-knowledge/units/{id}/reject`
- `POST /api/v1/admin/public-knowledge/units/{id}/suspend`
- `POST /api/v1/admin/public-knowledge/units/{id}/withdraw`
- `POST /api/v1/admin/public-knowledge/jobs`
- `GET /api/v1/admin/public-knowledge/jobs/{id}`

所有状态变更使用幂等键、乐观 revision 检查和审计日志。

## 16. 异步任务与资源控制

知识处理与用户查询使用不同任务队列和并发限制：

- 用户查询优先。
- 私有知识抽取次之。
- 公共候选生成、合并和历史回填最低。
- Ollama 后台任务设置独立并发上限和 CPU 配额。
- Qdrant 批量写入设置批次上限和退避。
- 任务保存持久游标，支持暂停、恢复和失败重试。
- 单个租户或单个会话失败不能阻塞其他任务。

搜索结果仅保存安全摘要，相同公共结论只生成一份向量，从源头控制 PostgreSQL、Qdrant 和模型上下文增长。

## 17. 异常与降级

- 未识别 AI 日志格式：记录适配器健康告警，不猜测内容。
- 脱敏失败：进入隔离队列，不生成公共候选。
- Ollama 不可用：任务保持待处理并退避，不阻塞事件上传。
- 公共候选冲突：进入人工审核，不自动合并。
- PostgreSQL 发布成功但向量写入失败：保持待索引，不对外可见。
- 公共索引不可用：降级为当前租户私有知识查询。
- 私有索引不可用：允许使用公共知识和模型补全，但明确缺少本租户证据。
- 来源撤回：重新计算公共知识验证状态，证据不足时暂停或撤回。
- 公共知识撤回：先从查询视图失效，再删除向量。
- 生成结果校验失败：允许一次结构化修正，再失败则使用确定性证据摘要。

任何降级都不得通过放宽 `tenant_id` 过滤来恢复结果。

## 18. 迁移与发布

### 18.1 无停机迁移

1. 扩展事件协议和适配器测试。
2. 新建公共知识、审核、冲突和任务表。
3. 建立独立公共 Qdrant 集合。
4. 使用新版抽取器回填租户私有过程知识。
5. 生成公共候选，但保持不可查询。
6. 在知识治理页面完成首批人工认证。
7. 启用影子检索，对比旧查询和全局查询。
8. 完成隐私、引用、覆盖率和性能验收。
9. 切换默认查询为 tenant_and_public。
10. 移除 Admin Web 普通查询中的项目选择，项目筛选迁移至诊断页。

### 18.2 回滚

- 客户端新事件类型可以被旧服务端安全忽略或暂存。
- 公共知识读取通过功能开关控制。
- 全局查询可回滚为当前已激活的私有知识版本。
- 公共 Qdrant 集合可以整体停用，不影响私有集合。
- PostgreSQL 表和历史数据不在回滚时删除。
- 已发布知识保留 revision 和撤回记录，禁止覆盖式回滚。

## 19. 测试策略

### 19.1 采集与清洗

- Codex、Claude Code、Cursor 的搜索调用、工具结果和显式分析摘要解析。
- `session_id`、`message_id` 和 `call_id` 关联。
- 未识别格式、截断日志、重复记录和检查点恢复。
- 路径、身份、设备、项目、代码、密钥、内部 URL 和查询参数脱敏。
- AI 命令正文不会通过工具结果重新泄漏。

### 19.2 知识与治理

- 单租户重复 AI 回答不能成为跨租户印证。
- 相同外部网页不能被计为多个独立来源。
- 跨租户相同结论去重和匿名来源统计。
- 冲突、不同版本和不同适用条件不会被错误合并。
- 确认、验证、认证、驳回、暂停、撤回和重新发布。
- 未认证知识不会进入公共向量集合。
- 来源撤回会触发重新评估。

### 19.3 检索与回答

- 不选择项目即可召回当前租户多个项目知识。
- 来源配额防止单个大项目占满上下文。
- 私有已验证结果优先于不适用的公共结论。
- 公共知识和模型补全具有明确来源标记。
- 重要结论引用有效、状态允许且 revision 一致。
- 不把过程经验错误表述成当前项目能力。

### 19.4 隔离与安全

- 普通租户无法从 API、错误信息、日志或 Qdrant payload 获得其他租户标识。
- 公共知识详情不能展开其他租户原始证据。
- 所有管理操作均验证权限并写入审计日志。
- 公共索引故障时不会退化为跨租户私有检索。

### 19.5 稳定性

- Ollama 高负载、超时、重启和任务恢复。
- PostgreSQL 与双 Qdrant 集合的一致性和重建。
- 大规模历史回填的暂停、续跑和失败隔离。
- 查询任务阶段持续更新，Admin Web 不出现无响应状态。

## 20. 验收标准

1. 智能查询不选择项目即可汇总当前租户全部项目知识。
2. 已认证公共知识可以被所有租户检索。
3. 每条公共知识都有 revision、平台认证记录和匿名来源统计。
4. 跨租户响应不包含来源租户、项目、设备、用户、路径或原始对话标识。
5. AI 搜索和工具过程能够形成私有候选知识，单次未验证内容不能自动公开。
6. 已验证私有结果与公共知识冲突时，回答采用适用环境匹配的私有结果，并生成冲突审核任务。
7. 撤回后的公共知识立即停止被新查询引用。
8. 每个重要结论都有私有知识、公共知识或模型通用知识来源标记。
9. 数据量最大的项目不会占满全部检索上下文。
10. 所有知识处理均为异步任务，失败可重试、可续跑、可审计。
11. 公共知识索引不可用时能够安全降级，且不放宽租户隔离。
12. 不产生员工排名、绩效评分或黑盒知识评分。

## 21. 实施拆分

本设计按以下顺序实施：

1. AI 搜索、工具结果和显式分析摘要采集。
2. 私有过程知识抽取器与证据模型扩展。
3. 公共知识数据库、审核权限和异步任务。
4. 二次脱敏、规范化、去重、独立性和冲突检测。
5. 公共 Qdrant 集合和发布一致性。
6. 知识治理 Admin Web。
7. 全局混合检索和回答契约。
8. 历史回填、影子检索、验收、切换和回滚演练。

每个阶段必须保持现有事件上传、活动记录和私有智能查询可用。
