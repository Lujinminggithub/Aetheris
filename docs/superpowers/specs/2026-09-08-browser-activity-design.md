# 浏览器活动采集与展示设计

## 目标

补齐 Aetheris 已规划但默认未启用的浏览器活动链路，使管理员能够配置允许采集的域名，并在活动记录、个人效能和智能查询中独立识别浏览器活动。

## 当前问题

- Windows Core 安装配置将 `browser_allowlist` 固定为空数组。Core 仅在白名单非空时初始化浏览器采集器，因此默认安装不会产生 `browser.page_view`。
- 服务端清洗事实已经支持 `activity_type=browser`，活动记录页面也已有浏览器筛选，但生产数据库当前不存在浏览器原始事件或清洗事实。
- 个人效能聚合没有独立的浏览器计数列，浏览器事件会落入“其他”。
- 浏览器采集策略只存在于本机静态配置，管理员无法从服务端统一管理，也无法判断客户端是否已应用策略。

## 边界与隐私

- 只支持 Chrome 和 Edge 的前台窗口，不读取完整浏览历史。
- 默认关闭采集；只有管理员显式启用并配置域名白名单后才采集。
- 只允许规范域名或其子域名匹配，不支持任意 URL、路径规则或通配符。
- 上传内容限定为域名、最长 512 字符的路径以及经过现有脱敏与 DLP 处理的可见文本摘要。
- 非白名单页面、认证信息、Cookie、表单值和浏览器配置文件不上传。
- 指标只描述活动构成，不用于员工排名、评分或绩效判断。

## 数据模型

新增 `browser_capture_policies`：

- `tenant_id`：租户主键。
- `enabled`：是否启用浏览器采集。
- `allowed_domains`：规范化、去重后的域名数组。
- `revision`：每次有效更新递增，用于客户端配置同步。
- `updated_by`、`created_at`、`updated_at`：审计信息。

个人效能日聚合增加 `browser_events`，指标定义版本升级。历史日期可通过既有重算任务回填。

## 接口

- `GET /api/v1/admin/browser-policy`：管理员读取租户策略。
- `PUT /api/v1/admin/browser-policy`：管理员更新启用状态和域名白名单。
- `GET /api/v1/device/browser-policy`：已注册设备使用 Device Token 获取最小策略投影。

管理接口沿用管理员会话、CSRF 和租户权限；设备接口沿用 Device Token 鉴权。所有域名在服务端做小写、去协议、去端口、去尾点、IDNA 可接受字符校验和数量限制。

## 客户端同步

Core 启动时和每次成功 heartbeat 后获取浏览器策略。仅当 `revision` 变化时更新本机配置并重建浏览器采集器；请求失败时保留最后一次有效策略并记录错误状态，不关闭当前有效采集。

浏览器采集失败不能阻塞终端、IDE、版本控制或 AI 事件上传。客户端状态文件记录策略版本、是否启用、白名单数量和最近错误，不记录域名明细。

## 管理后台

新增“浏览器采集”设置页：

- 启用开关。
- 每行一个域名的白名单编辑框。
- 保存状态、策略版本和隐私说明。

“活动记录”继续使用已有“浏览器”分类；“个人效能”的活动构成新增“浏览器活动”。无数据时仍显示 0，使未配置和无活动不会被误认为功能缺失。

## 验证

- 域名规范化和非法输入测试。
- 管理员/设备接口鉴权和租户隔离测试。
- Core 策略同步、失败保留旧策略和浏览器适配器启停测试。
- 清洗事实与个人效能浏览器分类测试。
- Admin Web 类型检查、构建和页面交互测试。
- 生产部署后验证策略接口、数据库迁移、服务健康和静态资源版本。
