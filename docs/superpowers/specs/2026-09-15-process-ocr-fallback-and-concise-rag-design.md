# 工作进程 OCR 保底与简洁智能查询设计

**日期：** 2026-09-15  
**状态：** 待实施  
**适用产品：** Aetheris Core、Lens、Forge、Nexus、Pulse  
**关联版本：** Windows Core 0.4.10 之后

## 1. 目标

本设计解决两个已经在真实数据中出现的问题：

1. 用户已授权的工作进程缺少专属适配器或适配器无法产生有效事件时，Aetheris 无法获得可组织的工作信号。
2. Nexus 智能查询把检索证据、实现细节和不确定性说明直接堆入主回答，导致简单业务问题得到冗长且偏离意图的技术分析。

首要目标是提高工作信号覆盖率，同时维持既定隐私边界；智能查询则默认提供与问题粒度一致的直接答案，并将证据和技术细节放到按需展开区域。

## 2. 非目标

- 不持续录屏，不保存截图，不构建屏幕回放。
- 不对未授权、系统、安全、即时通信或后台进程截图。
- 不通过 OCR 绕过浏览器白名单。
- 不把 OCR 文本视为高置信度原始事实。
- 不删除 Nexus 引用证据，不隐藏回答置信度。
- 不通过简单字符截断制造不完整回答。

## 3. 总体数据流

```text
用户授权工作进程
  -> 原生/专属适配器健康判断
  -> 连续 60 秒无有效事件
  -> 确认该进程当前处于前台
  -> 隐私与安全门禁
  -> 单窗口内存截图
  -> OCR
  -> DLP + 脱敏
  -> 五分钟指纹去重
  -> application.activity
  -> SQLite -> Gateway -> Forge -> Work Episode

用户问题
  -> 问题意图分类
  -> 授权范围检索
  -> 结构化回答生成
  -> 服务端契约校验与裁剪
  -> 主答案 + 可折叠依据
```

## 4. 工作进程 OCR 保底

### 4.1 触发条件

OCR 保底必须同时满足：

- 进程已由当前用户明确授权为 `allow_global` 或匹配当前项目的 `allow_project`。
- 进程窗口当前位于前台，窗口句柄和 PID 与授权身份一致。
- 该进程没有专属适配器，或专属适配器连续 60 秒没有产生有效事件。
- 最近五分钟内不存在相同窗口身份和 OCR 内容摘要的已接受保底事件。
- Core 队列未达到暂停水位，OCR Worker 当前无高优先级浏览器任务。

“有效事件”指已经通过项目授权、脱敏和本地去重，能够进入 AetherisEvent 的事件。适配器报错、空闲心跳或被拒绝事件不重置 60 秒计时。

### 4.2 永久排除

以下情况不截图，即使进程被错误授权：

- Windows 安全桌面、UAC、锁屏、登录界面和凭据 UI。
- 系统、安全、防病毒、打印和即时通信进程。
- 浏览器进程；Chrome/Edge 只能使用现有白名单 URL 采集链路。
- Aetheris 自身进程、OCR Worker 和安装程序。
- 后台、最小化、隐藏、无有效客户区或尺寸异常的窗口。
- UI Automation 检测到密码输入控件，或窗口类/可访问性角色属于凭据输入。

门禁失败只记录固定原因码和计数，不记录窗口标题、文本或路径。

### 4.3 截图与 OCR 生命周期

- 使用 Win32 前台窗口句柄获取客户区截图，不截取整个桌面。
- 单次只采集一帧；通用工作进程不自动滚动。
- 截图只作为内存中的 PIL/位图对象传给独立 OCR Worker。
- OCR 完成、超时或异常后立即释放图像对象和编码缓冲区。
- 不写临时 PNG、缓存图像、错误转储或日志附件。
- 复用已打包的 Tesseract.js `eng`、`chi_sim` 引擎和现有大小、文本长度限制。
- OCR 超时不超过 30 秒；同一时刻只运行一个通用保底 OCR。

### 4.4 文本处理与事件模型

OCR 原文先经过统一 DLP，再经过 Redactor。命中阻断规则时不生成正文事件，只更新健康状态。

成功事件使用：

```json
{
  "event_type": "application.activity",
  "payload": {
    "application_name": "受限规范名",
    "window_context": "脱敏后的短摘要",
    "visible_text": "脱敏 OCR 文本",
    "capture_method": "ocr_fallback",
    "ocr_languages": ["eng", "chi_sim"],
    "confidence": "low"
  }
}
```

不得包含：截图、绝对路径、命令行、PID、父进程链、发布者证书原文、窗口句柄或未脱敏 OCR 原文。PID 和父链只用于本地门禁与相关性判断。

### 4.5 去重与限流

事件指纹由设备内密钥保护的以下字段产生：

- 稳定进程身份键；
- 授权项目 ID；
- 规范化窗口上下文摘要；
- 脱敏文本摘要；
- 五分钟时间桶。

同一指纹每五分钟最多上传一次。每设备每分钟最多一次通用 OCR，每进程每五分钟最多一次。连续失败采用 1、2、5、10 分钟退避，成功后重置。

### 4.6 状态和可观测性

本地 Lens 与服务端 Adapter Health 增加 `application_ocr_fallback`：

- `eligible`：进入候选次数；
- `captured`：截图成功次数；
- `parsed`：OCR 和脱敏成功次数；
- `emitted`：进入事件队列次数；
- `skipped`：门禁或去重跳过次数；
- `failed`：固定错误码失败次数；
- `last_event_at`：最近成功事件时间。

允许的错误码包括 `not_foreground`、`native_adapter_recent`、`privacy_gate_blocked`、`window_unavailable`、`ocr_timeout`、`ocr_failed`、`dlp_blocked` 和 `duplicate_window_content`。

## 5. Forge 与 Work Episode

`application.activity` 规范化为：

- `fact_type=activity`
- `activity_type=application`
- `actor_origin=human`
- `confidence=low`
- `reason_codes=["ocr_fallback"]`

Work Episode 只显示安全摘要，例如“在设计工具中查看配置页面”。不得把完整 OCR 文本直接显示为动作标题。若同一时段存在专属适配器事实，专属事实优先，OCR 保底事实作为辅助证据且不重复增加 Pulse 活跃窗口。

## 6. 简洁智能查询

### 6.1 回答模式

Nexus 在检索前对问题进行确定性轻量分类：

- `direct`：是否、有无、能否、支持吗、存在吗等封闭确认问题。
- `numeric`：多少、几次、多久、比例等数值问题。
- `reason`：为什么、原因、根因等解释问题。
- `procedure`：如何、怎么做、步骤等操作问题。
- `analysis`：明确要求详细分析、证据、实现或对比。

无法确定时使用 `direct`，避免默认展开长分析。

### 6.2 结构化生成契约

模型必须返回严格 JSON：

```json
{
  "answer": "线路存在流量限制。",
  "answer_mode": "direct",
  "confidence": "high",
  "details": "",
  "citation_numbers": [1]
}
```

约束如下：

- `direct` 主答案最多 80 个中文字符，通常一至两句。
- `numeric` 先给数值和单位，再给一句口径说明。
- `reason` 最多三个直接原因，不主动展开实现细节。
- `procedure` 最多五个可执行步骤。
- `analysis` 才允许较长说明。
- `details` 默认不展示，仅在用户明确要求详细分析时使用。
- 引用编号必须来自输入证据；无证据时不得生成编号。
- 证据不足时回答“当前数据不足以确认。”

### 6.3 技术细节隔离

主答案禁止出现与业务问题无直接关系的内部细节，包括：

- 模型名、Embedding、Qdrant、向量、RAG、数据库表和内部 API。
- 未连接某服务器、未读取某日志、索引状态、Worker 或流水线状态。
- 代码变量名、类名、信用桶实现和算法细节，除非用户明确询问实现或详细原因。
- 与问题结论无关的替代假设和排查过程。

业务本身包含技术术语时允许保留必要术语。例如用户问限速实现时可解释限速器，但用户只问“有没有限制”时只回答存在与否。

### 6.4 服务端回答校验

服务端不信任模型输出，必须执行：

- JSON 结构、模式值、置信度和引用编号校验。
- `direct` 长度和句子数限制。
- 内部技术细节词表检测。
- 引用必须属于本次授权检索结果。
- 模型返回非法结构时进行一次带错误反馈的重试。
- 重试仍失败时，使用确定性保底答案，不把模型原文透传给前端。

服务端保存结构化答案，而不是只保存一个自由文本字段。兼容旧查询时仍产生 `answer` 字段。

### 6.5 前端呈现

Admin Web 智能查询默认显示：

- 直接答案；
- 置信度；
- “查看依据”折叠按钮；
- 引用数量。

展开后才显示证据卡片、时间、项目和安全摘要。默认界面不显示模型名、Embedding 模型、向量状态等技术实现字段；系统不可用时显示用户可理解的产品状态。

用户可在问题中明确要求“详细说明”触发 `analysis`，首期不新增额外模式开关。

## 7. 安全与失败处理

- OCR 保底默认对已授权工作进程启用，但用户可在本地 Lens 按进程停用；状态同步到服务端。
- 任何截图、OCR 或 DLP 异常均采取不上传正文的失败关闭策略。
- 高风险 OCR 原文不进入普通队列；首期直接阻断，不扩大加密隔离区的使用范围。
- 智能查询的证据继续执行租户、主体、设备和项目授权过滤。
- 模型输出不得改变引用范围，也不得触发外部工具或数据读取。
- 所有状态日志只包含固定原因码和计数。

## 8. 测试与验收

### 8.1 Core

- 已授权前台工作进程连续 60 秒无专属事件后触发一次截图。
- 59 秒不触发，60 秒触发；专属事件到达后计时重置。
- 未授权、后台、浏览器、安全和密码输入窗口不截图。
- 截图对象不写入磁盘，OCR 完成后释放。
- OCR 文本经 DLP 和脱敏后才形成事件。
- 相同内容五分钟内只上传一次，下一时间桶允许再次产生事件。
- 队列高水位和 OCR 忙时跳过，不阻塞主采集循环。

### 8.2 Forge、Episode 与 Pulse

- `application.activity` 形成低置信度、可解释事实。
- Episode 只展示安全摘要，不展示完整 OCR 文本。
- 同时存在专属事件时不重复计算活跃时间。

### 8.3 Nexus

- “线路有没有流量限制”只返回类似“线路存在流量限制。”的直接答案。
- “为什么线路会限速”返回简短原因和引用。
- “详细说明限速实现和证据”允许返回实现细节。
- 模型名、向量库和内部日志状态不出现在默认主答案。
- 非法 JSON、虚假引用、过长回答和内部细节触发重试或确定性降级。
- 前端默认折叠依据，展开后引用仍可追溯到授权事件。

## 9. 发布与回滚

- Core、Go Server 和 Admin Web 同版本发布，安装包继续使用单一 NSIS EXE。
- 发布前保留服务器二进制、Admin Web 静态目录和客户端安装包备份。
- OCR 保底可通过服务端策略整体关闭；关闭不影响专属适配器。
- 新问答契约异常时可回滚生成器和前端，既有检索文档与引用无需重建。
- 部署后验证 `/healthz`、客户端下载、OCR 健康快照、结构化查询和证据展开。
