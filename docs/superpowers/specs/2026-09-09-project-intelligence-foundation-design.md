# Aetheris 项目智能化基础设计

**日期：** 2026-09-09  
**状态：** 待用户审阅  
**范围：** 项目注册与历史归属、工作片段生产、适配器健康诊断、本地进程授权，以及依赖这些基础能力的采集适配器扩展

## 1. 建设目标

本设计用于补齐“采集开发活动原始数据”与“形成可解释工作成果”之间的能力缺口。实施顺序固定如下：

1. 修复项目注册并回填历史项目归属。
2. 建设生产可用的工作片段投影。
3. 增加适配器健康诊断。
4. 增加本地进程发现和持久授权。
5. 扩展 Claude Code、Cursor、VS Code、Visual Studio、GitHub Copilot、浏览器、Git 和终端的真实数据格式。

最终效果必须让管理员能够理解：某个人在哪个逻辑项目上工作、工作的目标是什么、发生了哪些动作和决策、如何验证、最终结果是什么，以及每项结论由哪些源事件支撑。本地用户通过 Lens 查看并控制进程授权和采集健康状态。

## 2. 已确认决策

- 一个 Git 仓库对应一个逻辑项目。规范化远程仓库指纹相同的多个克隆目录和 Git 工作树，默认归入同一逻辑项目。
- 每个克隆目录或工作树仍作为独立项目位置保留，用于诊断和归属证据。
- 原始 `AetherisEvent` 记录保持不可变。历史归属通过带版本的派生映射表达，不改写原始事件。
- `project-*` 等内部标识可以出现在诊断详情中，但不得作为正常产品界面的项目名称。
- 不把本地项目绝对路径作为项目注册元数据上传。Core 只上传安全显示名称和使用密钥生成的不可逆身份指纹。
- 无法确定的归属保持未归属并进入复核，不得静默合并到已确认项目。
- 工作片段中的每项陈述都必须有源事件证据。缺少证据的模型生成内容不得进入正式投影。
- Ollama 是默认的可选摘要运行时。没有 Ollama 时，确定性工作片段构建仍必须运行。Dify 不拥有规范数据、项目身份、检索或引用。
- 进程授权属于当前 Windows 用户会话。Windows 服务可以监管并拉起 Core，但不显示授权界面，也不采集其他用户会话。
- 同一进程身份在同一 Windows 用户空间内只提醒一次，除非可信身份发生实质变化或用户主动重置决定。
- 浏览器白名单采用主机名精确匹配和子域名后缀匹配，禁止任意字符串包含匹配。

## 3. 总体架构

```text
Windows Core
  项目扫描器
    -> 本地项目注册
    -> 安全项目元数据同步
  进程监视器
    -> 授权前身份检查
    -> 本地授权存储
    -> 适配器运行资格判断
  采集适配器
    -> 适配器健康注册表
    -> 已脱敏 AetherisEvent
    -> 有界 SQLite 队列
    -> Gateway

Go 服务端
  项目注册表
    -> 逻辑项目与项目位置映射
    -> 历史归属任务
  不可变事件存储
    -> 清洗事实
    -> 工作片段任务
    -> 检索、Pulse、导出
  设备健康摘要
    -> 管理端采集覆盖页面

本地 Lens
  项目位置与待归类项
  本地个人工作片段与证据
  进程授权待处理列表
  适配器详细诊断
  本地修正与重置控制
```

项目注册表是所有后续能力的共同基础。工作片段、适配器覆盖率、进程与项目授权、检索、Pulse 和导出统一使用逻辑项目身份，不再各自从事件载荷临时推导项目名称。

## 4. 项目身份模型

### 4.1 本地项目身份

为兼容现有事件，Core 继续保留本地项目标识。新的本地注册记录增加稳定元数据：

```json
{
  "local_project_id": "project-7db1f31bb62a38ed",
  "display_name": "jtagent",
  "vcs": "git",
  "remote_fingerprint": "hmac-sha256:...",
  "root_fingerprint": "hmac-sha256:...",
  "workspace_kind": "primary",
  "worktree_name": "",
  "active": true,
  "metadata_revision": 3
}
```

`display_name` 从已授权根目录的末级名称生成，允许用户在本地修改，同步前必须脱敏并限制长度。`remote_fingerprint` 使用租户级项目身份密钥对规范化 Git 远程地址计算；该密钥在设备注册时下发，并在本地使用 DPAPI 保护，远程地址原文永不上传。不同设备使用同一版本的租户密钥，才能为同一仓库生成相同指纹。`root_fingerprint` 使用独立的设备级本地密钥，避免本地路径跨设备关联。`workspace_kind` 取值为 `primary`、`clone`、`worktree` 或 `non_vcs`。

远程地址规范化必须删除凭据、统一协议和主机名大小写、移除末尾 `.git`，并在计算指纹前统一 SSH 与 HTTPS 表达。没有远程地址的仓库使用 `(device_id, root_fingerprint)` 作为身份，不允许跨设备自动合并。

项目身份密钥必须带有明确版本。轮换期间只接受当前版本和上一个版本的指纹，完成新绑定后停用旧版本。项目身份密钥不得用于命令指纹、登录凭据、内容加密或其他用途。

### 4.2 服务端项目注册表

Go 服务端新增两个持久实体。

`logical_projects` 表：

- `id`：服务端生成的稳定标识。
- `tenant_id`：租户所有权边界。
- `display_name`：安全的产品展示名称。
- `vcs`：`git`、`svn` 或 `none`。
- `remote_fingerprint`：可为空的远程仓库身份指纹。
- `status`：`active`、`archived` 或 `needs_review`。
- `created_at`、`updated_at`、`metadata_revision`：创建、更新时间和元数据版本。

`project_locations` 表：

- `id`：服务端生成的位置标识。
- `tenant_id`、`logical_project_id`、`device_id`：租户、逻辑项目和设备关系。
- `local_project_id`：现有 Core 项目标识。
- `display_name`、`root_fingerprint`、`workspace_kind`、`worktree_name`：安全位置元数据。
- `active`、`first_seen_at`、`last_seen_at`、`metadata_revision`：状态、时间和版本。
- 唯一键为 `(tenant_id, device_id, local_project_id)`。

迁移期间保留现有 `projects` 表，确保当前事件外键和接口继续工作。新投影通过 `project_locations.local_project_id` 把 `events.project_id` 解析为 `logical_projects.id`。

### 4.3 自动归并规则

自动归并按以下顺序执行：

1. 已存在的 `(tenant_id, device_id, local_project_id)` 精确绑定。
2. 租户内相同且非空的 `remote_fingerprint`。
3. 管理员或本地用户此前确认的映射。
4. 创建新的逻辑项目。

仅显示名称相同不得触发项目合并。名称冲突或存在多个可能的逻辑项目时，状态必须为 `needs_review`。

已确认的默认规则是：共享同一 Git 远程仓库的克隆目录和工作树归入同一逻辑项目。项目位置仍显示在证据和诊断中，以便追踪具体设备和工作树。

### 4.4 项目注册接口

Core 使用设备凭据，把项目注册批次幂等发送到 `PUT /api/v1/device/projects`。每条记录包含本地项目身份模型中的字段。响应格式如下：

```json
{
  "registry_revision": 12,
  "projects": [
    {
      "local_project_id": "project-7db1f31bb62a38ed",
      "logical_project_id": "logical-project-...",
      "display_name": "jtagent",
      "resolution": "remote_fingerprint",
      "needs_review": false
    }
  ]
}
```

Core 独立于事件上传重试项目注册。项目注册失败不得删除本地配置，也不得阻断已经授权的离线采集；事件继续保留在本地队列中，等待正常上传。

## 5. 历史项目归属回填

### 5.1 派生映射

历史归属保存在 `project_attributions` 表中：

- `tenant_id`、`event_id`、`logical_project_id`、`project_location_id`：租户、事件、逻辑项目和位置关系。
- `method`：`exact_binding`、`remote_fingerprint`、`safe_label`、`authorized_root`、`session_correlation`、`manual` 或 `unresolved`。
- `confidence`：`high`、`medium` 或 `low`。
- `evidence`：只包含安全标识、规则名称和哈希的 JSON。
- `rule_version`、`needs_review`、`created_at`：规则版本、复核状态和创建时间。
- 主键为 `(tenant_id, event_id, rule_version)`。

此表不得复制绝对路径或未脱敏的远程地址。

### 5.2 归属判定顺序

历史回填任务依次应用以下规则：

1. 当前事件 `project_id` 与设备对应的精确项目位置绑定。
2. 与事件现有安全项目标签一致的已确认注册记录。
3. 已存在于脱敏事件投影中的授权根目录归属。
4. AI 会话与同一会话内高置信度项目事件的关联。
5. 同一设备和项目位置上，在限定时间范围内发生的 Git、终端或 IDE 活动关联。
6. `Codex`、`Claude Code`、`Cursor` 等工具兜底项目，标记为未归属，并从项目级结论中排除。

规则 1 至 3 可以自动发布。规则 4 和 5 只有在候选唯一且达到配置的置信度阈值时才能发布。存在歧义的结果进入复核队列。

### 5.3 执行与回滚

历史回填支持四种模式：

- `dry-run`：只计算数量和冲突，不写入映射。
- `apply`：按有界批次写入映射。
- `resume`：从持久检查点继续执行。
- `activate`：原子切换租户当前启用的归属规则版本。

计算和启用必须分离。任务失败时继续使用上一个规则版本。回滚只切换启用版本指针，不改写或删除原始事件。

启用新版本后，按顺序重新计算：

1. 清洗事件事实；
2. 工作片段；
3. 检索文档和向量引用；
4. Pulse 与效能聚合；
5. 导出清单。

所有任务必须幂等并记录来源规则版本。生产环境初始批次大小为 10,000 条事件，并允许配置。当前数据量验收必须使用现有服务端数据，不能只使用小型模拟数据。

### 5.4 产品展示规则

正常项目选择器显示 `logical_projects.display_name`。诊断详情可以显示逻辑项目标识和旧本地项目标识。未归属事件显示为“未归属 · Codex”等中文名称，界面不得把裸露的 `project-*` 当作友好名称。

## 6. 工作片段模型与处理流程

工作片段使用同一数据结构形成两种产品投影。本地投影只覆盖当前 Windows 用户和当前设备，由 Lens 展示；服务端投影覆盖租户内已授权数据，由管理员查看。两种投影都不修改不可变源事件，并采用相同的证据约束。

### 6.1 投影数据结构

`work_episodes` 表保存当前版本和历史版本：

- `episode_id`、`tenant_id`、`subject_id`、`logical_project_id`：工作片段及其主体归属。
- `revision`、`status`、`started_at`、`ended_at`：版本、状态和时间范围。
- `title`、`objective`、`context`、`outcome`：标题、目标、上下文和结果。
- `confidence`、`needs_review`、`generator`、`generator_version`：置信度、复核状态和生成器信息。
- `attribution_rule_version`、`cleaning_rule_version`：归属和清洗规则版本。
- `supersedes_revision`、`created_at`：被替代版本和创建时间。

以下子表保存有类型且有顺序的明细：

- `work_episode_actions`：参与方、动作类型、安全摘要、发生时间。
- `work_episode_decisions`：决策、依据和置信度。
- `work_episode_validations`：验证类型、结果和安全摘要。
- `work_episode_next_actions`：按顺序排列的后续事项。
- `work_episode_evidence`：工作片段版本、章节、条目标识、事件标识和引用原因。

每个正式发布的目标、动作、决策、验证、结果和后续事项至少包含一条证据记录。

### 6.2 候选工作片段构建

Forge 通过确定性规则构建候选项：

1. 使用逻辑项目和主体作为主要范围。
2. 保留明确的 AI 会话标识和关联标识。
3. 使用设备、项目位置和时间，把相邻终端、IDE、Git 和浏览器事实关联进来。
4. 超过可配置的无活动间隔后切分候选项，默认间隔为 30 分钟。
5. 没有证据时，不得把工具兜底项目中的未归属事件关联到已确认项目。

初始目标来自最早的有效用户消息或明确任务记录。动作来自规范化 AI 工具调用、终端命令、IDE 事件、Git 事实和浏览器事实。验证必须具有测试、构建、静态分析、运行健康检查或明确用户确认等证据。发出命令本身不能证明命令执行成功。

### 6.3 确定性处理和模型辅助处理

确定性阶段建立完整证据图和安全结构化摘要；没有模型运行时也必须可用。

Ollama 健康时，Forge 可以只使用已提供证据请求严格 JSON 摘要。返回内容必须通过结构校验，缺少有效证据标识的陈述必须丢弃。模型超时或返回无效内容时，保留确定性工作片段并设置 `needs_review=true`，不得阻断事件入库或删除旧投影。

Dify 可以通过适配器编排可选工作流，但只能接收经过授权和脱敏的证据。所有提示词、数据、索引、证据链接和存储结果均由 Aetheris 管理。

Core 基于近期本地事件缓存维护有界的本地工作片段投影，供个人 Lens 使用，不得暴露其他用户或设备。服务端 Forge 根据已接受的服务端事实独立计算权威管理投影。本地修正必须创建替代事件并通过正常队列同步；服务端确认后，两种投影通过版本处理收敛。

### 6.4 修订与删除

事件替代、事件删除、项目重新分配、授权撤销或规则版本启用时，受影响工作片段必须标记为过期。重新计算写入新版本，并原子更新当前版本指针。检索、Pulse 和导出只能使用当前启用版本。

## 7. 适配器健康诊断

### 7.1 本地健康模型

每个适配器发布一个 `AdapterHealthSnapshot`：

```json
{
  "adapter_id": "claude_code",
  "state": "active",
  "capability_version": "2",
  "detected_format": "claude-jsonl-v3",
  "last_scan_at": "RFC3339",
  "last_success_at": "RFC3339",
  "last_event_at": "RFC3339",
  "discovered": 20,
  "parsed": 18,
  "skipped": 2,
  "failed": 0,
  "lag_seconds": 3,
  "error_code": "",
  "error_stage": ""
}
```

允许的状态为 `active`、`idle`、`disabled`、`source_missing`、`permission_denied`、`format_changed`、`dependency_missing` 和 `error`。错误码必须稳定，且不得包含采集内容、原始路径、网址、凭据、OCR 文本或截图。

Core 把详细快照写入本地 SQLite，并通过需要认证的回环 Lens 接口提供。设备心跳只向服务端发送状态、计数、版本、时间和安全错误码。

### 7.2 分阶段诊断

多阶段适配器必须报告具体失败阶段。浏览器阶段包括：`foreground_window`、`process_identity`、`url_read`、`allowlist`、`capture`、`scroll`、`ocr`、`redaction` 和 `emit`。结构化会话阶段包括：`source_discovery`、`open_readonly`、`format_detect`、`parse`、`checkpoint`、`redaction` 和 `emit`。

预期没有新数据不能报告为成功。例如：缺少 VS Code 桥接文件应报告 `source_missing`；Claude 历史文件有效但没有变化应报告 `idle`；无法识别 Cursor 数据结构应报告 `format_changed`。

### 7.3 产品界面

本地 Lens 显示完整诊断和恢复操作。Admin Web 增加“采集覆盖”页面，按设备展示适配器状态、最近事件、延迟、格式版本和安全失败原因。服务端原始事件数量必须与适配器健康分开展示，使管理员能够区分“健康但空闲”和“采集器损坏”。

## 8. 本地进程发现与授权

### 8.1 进程身份

Core 使用运行在当前活动控制台用户会话中的 Windows 原生发现器，替换只依赖 `tasklist` 的身份识别。授权前只允许读取：

- 进程标识和父进程标识；
- 可执行文件名和规范化路径；
- 产品名称和版本；
- Authenticode 发布者和签名状态；
- 未签名或无法验证程序的文件哈希。

已签名应用的稳定提醒身份为 `(user_sid, publisher_identity, normalized_executable_path)`；未签名应用为 `(user_sid, normalized_executable_path, binary_hash)`。进程标识变化不得创建新身份。发布者、路径或未签名文件哈希改变时需要重新复核；同一可信路径下正常的已签名版本升级不重复提醒。

### 8.2 授权状态

`process_consent` 支持：

- `pending`：已发现但从未采集。
- `allow_global`：对所有已授权项目均视为工作相关。
- `allow_project`：只对指定逻辑项目视为工作相关。
- `deny`：当前不监控，但保留在本地供以后复核。
- `always_ignore`：持续排除，直到用户手动重置。
- `default_excluded`：根据产品策略默认排除，不提醒。

主键必须包含 Windows 用户 SID 和稳定进程身份。记录包含首次发现、最近发现、提醒时间、决定时间、策略版本和安全身份元数据。授权决定只保存在本地。服务端可以接收健康状态汇总数量，但不得接收用户拒绝的个人应用列表。

### 8.3 用户流程

1. Core 发现新的进程身份。
2. 在任何提醒前执行默认排除规则。
3. 从本地 SQLite 读取已有授权决定。
4. 新的待确认身份只创建一次托盘通知和一个 Lens 待处理项。
5. 用户选择“工作相关”“仅指定项目”或“不监控”。
6. 只有存在允许决定和有效项目授权后才能开始采集。
7. 用户以后可以在 Lens 修改或重置决定。

用户关闭或错过通知时，Lens 中的待处理项仍然保留。Core 不得对同一个待确认身份重复弹出通知。Aetheris 自身进程、Windows 系统进程、即时通信、打印、安全、凭据和密码管理器进程默认排除。

### 8.4 项目关联

已允许进程按以下顺序关联项目：

1. 明确的项目范围授权；
2. 适配器提供的工作区或解决方案身份；
3. 从父进程继承的项目上下文；
4. 唯一活动的已授权项目位置；
5. 本地待归类复核。

项目上下文存在歧义时，阻止该进程的内容采集，但不得把项目管理问题当作安装失败。

## 9. 采集适配器扩展

只有项目注册、健康报告和进程授权投入运行后，才能继续扩展适配器。每个适配器必须具备格式检测、只读访问、持久检查点、有界解析、落盘前脱敏、安全健康报告和真实格式测试样本。

实施顺序如下：

1. Claude Code 多版本 JSONL 历史和项目映射。
2. Cursor 的 composer、agent、bubble、工作区和项目数据结构。
3. VS Code 原生活动桥接和 GitHub Copilot 会话存储。
4. Visual Studio 解决方案、构建、调试和测试桥接事件。
5. Chrome 和 Edge 前台网址获取、白名单判断、内存截图、有界滚动拼接、OCR、DLP 和事件生成。
6. Git、终端和 AI 会话的跨源关联，包括可获取的验证结果证据。

浏览器域名配置接受 `example.com` 形式的规范主机名，并匹配 `example.com` 本身及以 `.example.com` 结尾的子域名；不得匹配 `notexample.com`、路径、任意子串或通配符输入。

## 10. 接口与界面变更

新增服务端接口：

- `PUT /api/v1/device/projects`：幂等注册项目。
- `GET /api/v1/admin/projects`：查询逻辑项目、项目位置、冲突和数量。
- `POST /api/v1/admin/projects/merge`：审计记录完整的逻辑项目合并。
- `POST /api/v1/admin/projects/reassign`：审计记录完整的归属修正。
- `POST /api/v1/admin/project-backfills`：试运行或应用归属规则版本。
- `GET /api/v1/admin/project-backfills/{id}`：查询进度、冲突和启用状态。
- `GET /api/v1/admin/work-episodes`：查询经过筛选的当前工作片段。
- `GET /api/v1/admin/work-episodes/{id}`：查询版本和证据详情。
- `GET /api/v1/admin/adapter-health`：查询设备采集覆盖摘要。

新增本地 Lens 接口继续绑定回环地址，并使用现有本地控制凭据：

- `GET /local/v1/projects` 及项目位置复核操作。
- `GET /local/v1/work-episodes` 和 `GET /local/v1/work-episodes/{id}`，只允许访问当前本地用户和设备。
- `GET /local/v1/adapters/health`。
- `GET /local/v1/processes/pending`。
- `PUT /local/v1/processes/{identity}/consent`。
- `DELETE /local/v1/processes/{identity}/consent`：重置决定。

Admin Web 增加“项目”“工作片段”和“采集覆盖”页面。本地 Lens 增加“个人工作片段”“项目”“采集健康”和“进程授权”页面。Admin Web 不提供远程查看或修改用户已拒绝个人进程列表的能力。

## 11. 安全与隐私

- 截图和滚动帧只存在于内存中，OCR 和 DLP 处理完成后立即释放引用。
- 项目注册和适配器健康载荷不得包含本地绝对路径或 Git 远程地址原文。
- 历史归属证据只包含安全标签、事件标识、规则名称和不可逆指纹。
- 原始事件内容不得写入日志、健康快照、任务检查点或审计记录。
- 设备凭据与本地控制凭据必须分离。
- 租户项目身份密钥必须用途独立、带版本、只下发到已注册设备，并使用 DPAPI 在本地保护。
- 项目合并、重新分配、回填启用和工作片段修正必须记录审计日志。
- 被拒绝和默认排除的进程身份只保存在本地，服务端最多接收汇总数量。
- 进程授权不得绕过浏览器白名单、项目授权、脱敏、DLP 或处理许可。
- 即使旧原始事件包含历史路径来源，新接口和界面也不得暴露该路径，只能返回安全项目名称。

## 12. 失败处理与回滚

- 项目注册失败时保留本地注册表，并使用有界退避重试。
- 项目元数据冲突时创建复核项，不覆盖已确认名称。
- 回填计算与启用分离；启用提交前始终使用上一个版本。
- 工作片段生成失败时保留原始事件和上一个有效版本。
- Ollama 或 Dify 不可用时降级为确定性工作片段。
- 单个适配器异常只更新自身健康状态，不得停止其他适配器。
- 进程监视器失败时停止新进程采集、报告本地错误，并保留已有授权决定。
- 在新投影通过验收前，数据库迁移只做增量添加；迁移期间保留现有项目和活动接口。
- 部署回滚恢复上一版服务端程序和启用规则版本指针，不回滚不可变事件。

## 13. 验证策略

所有边界均采用 TDD：

- Python 单元测试覆盖远程地址规范化、指纹、本地注册表、健康状态、Windows 进程身份、授权状态转换和适配器。
- 跨设备测试证明：同一远程仓库在相同租户密钥下得到相同指纹，不同租户密钥和设备级根目录密钥之间无法关联。
- Go 单元测试覆盖项目匹配、接口校验、回填规则、工作片段证据约束、版本启用和健康聚合。
- PostgreSQL 迁移测试覆盖约束、幂等性、版本启用和回滚。
- React 测试覆盖产品名称、未归属状态、复核操作、工作片段证据、适配器健康和本地授权交互。
- 根据 OpenAPI 和共享 JSON Schema 建立契约测试。
- 建立从真实格式本地样本经过 SQLite、Gateway、PostgreSQL、投影直到 Admin Web 的端到端测试。
- Windows 验收覆盖托盘通知、跨 Core 重启和 Windows 重启的一次提醒、进程标识变化、已签名升级、默认排除和不显示命令行窗口。
- 浏览器验收证明非白名单页面不会产生截图、OCR 工作、文件、事件或包含内容的健康信息。

真实格式样本进入仓库前必须最小化并人工脱敏。模拟样本可用于边界情况，但不能作为适配器已完成的唯一证据。

## 14. 交付阶段与验收门槛

### R1：项目契约与注册

交付增量数据库迁移、本地项目元数据、设备项目注册接口和管理端逻辑项目页面。验收门槛：新事件解析为安全逻辑项目名称，现有事件入库保持兼容。

### R2：历史归属

交付试运行报告、冲突复核、应用、续跑、启用任务及派生系统重算。验收门槛：当前服务端数据可幂等完成处理；正常界面不再出现裸露项目哈希；未归属数量明确可见。

### R3：工作片段

交付数据结构、确定性构建器、可选 Ollama 增强、版本、证据详情、本地个人 Lens 页面和服务端管理页面。验收门槛：代表性会话只有在存在事件证据时才能生成目标、动作、验证和结果；Lens 不得查询其他用户或设备。

### R4：适配器健康

交付本地健康注册表、分阶段诊断、心跳摘要、本地 Lens 健康页面和管理端采集覆盖页面。验收门槛：浏览器和 IDE 为零事件时，能够显示准确且安全的失败阶段。

### R5：进程授权

交付原生身份发现、按用户持久决定、一次性通知、Lens 待处理列表、项目范围授权和默认排除。验收门槛：未知进程只提醒一次；Core 和 Windows 重启后决定仍然有效；授权前不产生任何内容采集事件。

### R6：适配器扩展

按第 9 节顺序交付各适配器。每个适配器都有独立的真实格式端到端验收，不得仅凭解析器单元测试就标记为已支持。

### R7：集成验收

重新构建 Windows 安装程序和服务端发布包，在现有安装上执行升级，演练回滚，运行隐私扫描，验证 512 MB 本地队列和 100 GB 服务端磁盘预算控制，并执行真实项目验收流程。

## 15. 总体验收标准

1. 项目列表使用稳定安全名称，并按规范化 Git 远程仓库指纹归并克隆目录和工作树。
2. 每条历史事件都具有当前逻辑项目归属，或者明确的未归属原因。
3. 历史回填支持试运行、续跑、启用和回滚，且不改写原始事件。
4. 工作片段包含目标、动作、决策、验证、结果、置信度和源证据。
5. 正式发布的工作片段陈述不得缺少证据引用。
6. 适配器健康能够区分空闲、缺少数据源、权限失败、格式变化、依赖失败和运行错误。
7. 浏览器失败能够定位具体阶段，同时磁盘和日志中不出现截图或 OCR 文本。
8. 新的未知进程身份在每个 Windows 用户空间内只提醒一次，并保持待确认直到用户处理。
9. 被拒绝的进程或项目归属有歧义时，不得产生可上传的采集内容。
10. Claude Code、Cursor、VS Code 与 GitHub Copilot、Visual Studio 和浏览器适配器必须分别通过真实格式客户端到服务端验收后，才能标记为已支持。
11. 增量迁移期间，现有事件入库、设备注册、管理员认证、导出、检索和 Pulse 接口保持可用。
12. 服务端磁盘占用保持在 100 GB 以内，历史重算使用有界批次并提供可观察进度。

## 16. 明确不在本期范围内

- 通过修改项目身份来重写不可变历史 `AetherisEvent`。
- 仅因为目录名称相同就合并项目。
- 上传绝对路径、Git 远程地址原文、被拒绝的进程清单、截图或 OCR 帧。
- 浏览器插件、CDP 附加、连续录制或任意域名子串匹配。
- 由远程管理员审批本地用户的个人进程列表。
- 黑箱效能评分、员工排名或缺少证据的工作完成结论。
- 仅依据模拟单元测试就把适配器标记为已完成。
