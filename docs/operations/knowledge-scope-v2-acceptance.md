# 知识范围 v2 验收

## 1. 知识边界

公共知识必须同时具备：

- 明确的 `domains`，不得为空。
- 可解释的 `entities`。
- `scope_state=classified`。
- 问题与结论领域兼容。
- 不包含代理调度、任务包装或流程指令。
- 平台认证理由不少于 20 个字符，并说明领域、实体、适用条件和证据。

`研发过程知识`、未知领域、`Agent message`、`FINAL_ANSWER`、委派子代理和“继续规格实施”等内容不得进入公共索引。

## 2. 检索顺序

```text
问题领域识别
  -> 领域硬过滤
  -> 关键词与向量召回
  -> 验证状态排序
  -> 跨项目去重
  -> 回答生成
  -> 回答领域复核
```

认证状态不能绕过领域过滤。

## 3. 固定回归

### DLP

- 问题：`Windows DLP 的实现原理`
- 必须覆盖：内容采集、OCR/文本提取、策略匹配、阻断、审计。
- 禁止出现：FEC、公网丢包、媒体队列、`nb_live.c`。

### EDR

- 问题：`Windows EDR 如何实现`
- 必须覆盖：内核采集、用户态分析、检测关联、响应。
- 禁止用 DLP OCR 结论替代端点检测机制。

### 网络传输

- 问题：`FEC 如何处理 UDP 丢包`
- 允许：FEC、UDP、冗余、丢包、媒体队列。
- 禁止混入 DLP 策略和 OCR。

## 4. 发布门禁

- 未知领域进入公共索引数量必须为 0。
- `研发过程知识`进入公共索引数量必须为 0。
- 固定 DLP 禁止实体命中率必须为 0。
- 公共知识保持 `shadow`，直至固定回归全部通过。

## 5. 原子知识点演进

历史过程知识已通过 `process_knowledge_claims` 拆成原子知识候选。每个 claim 只表达一个可判断结论，并保存领域、实体、适用条件、验证状态和来源证据。多个 claim 通过关系表组成过程知识链：

```text
问题 -> 探索 -> 决策 -> 实施 -> 测试 -> 最终结果
```

智能查询默认召回原子 claim；用户询问研发过程时再展开关系链和原始会话。

原子知识候选必须满足以下门禁：

- 至少关联一条来源证据；没有证据的结论不生成候选。
- 知识点正文命中一个领域时，以正文领域为准，并要求该领域与父问题兼容。
- 知识点正文未命中领域时，只有父问题恰好属于一个领域才允许继承。
- 父问题或知识点存在多领域歧义时不生成候选，禁止按排序任取一个领域。
- 箭头流程片段、纯源码路径、长哈希、本机源码链接、Shell 命令、安装包链接、语言标签、日志残片、单纯大小记录、测试或构建状态、实施动作、代理执行叙述不生成候选。
- 候选必须是以句号、问号或感叹号结束的完整陈述；分号列表项、未闭合代码标记、内嵌流程箭头和绝对本机路径不生成候选。
- 原始事件、过程知识单元和证据保持不可变；规则调整后只重建派生 claim 和关系。
- 新生成的 claim 初始状态为 `candidate`，必须在 Admin Web 的“原子知识审核”中人工确认或拒绝。
- 公共候选构建器只读取 `confirmed` claim；公共知识仍需完成平台认证后才能发布和进入公共索引。
