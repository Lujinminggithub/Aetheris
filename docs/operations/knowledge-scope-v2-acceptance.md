# 知识范围 v2 验收

## 1. 知识边界

公共知识必须同时具备：

- 明确的 `domains`，不得为空。
- 可解释的 `entities`。
- `scope_state=classified`。
- 问题与结论领域兼容。
- 不包含代理调度、任务包装或流程指令。
- 平台认证理由不少于 20 个字符，并说明领域、实体、适用条件和证据。

`研发过程知识`、未知领域、`Agent message`、`FINAL_ANSWER`、委派子代理和“继续规格实施”等内容不得进入公共索引。

## 2. 检索顺序

```text
问题领域识别
  -> 领域硬过滤
  -> 关键词与向量召回
  -> 验证状态排序
  -> 跨项目去重
  -> 回答生成
  -> 回答领域复核
```

认证状态不能绕过领域过滤。

## 3. 固定回归

### DLP

- 问题：`Windows DLP 的实现原理`
- 必须覆盖：内容采集、OCR/文本提取、策略匹配、阻断、审计。
- 禁止出现：FEC、公网丢包、媒体队列、`nb_live.c`。

### EDR

- 问题：`Windows EDR 如何实现`
- 必须覆盖：内核采集、用户态分析、检测关联、响应。
- 禁止用 DLP OCR 结论替代端点检测机制。

### 网络传输

- 问题：`FEC 如何处理 UDP 丢包`
- 允许：FEC、UDP、冗余、丢包、媒体队列。
- 禁止混入 DLP 策略和 OCR。

## 4. 发布门禁

- 未知领域进入公共索引数量必须为 0。
- `研发过程知识`进入公共索引数量必须为 0。
- 固定 DLP 禁止实体命中率必须为 0。
- 公共知识保持 `shadow`，直至固定回归全部通过。

## 5. 原子知识点演进

下一阶段将长结论拆成原子 `claims`。每个 claim 只表达一个可判断结论，并保存领域、实体、适用条件、验证状态和来源证据。多个 claim 通过前置、因果、替代、验证、否定和修订关系组成过程知识链：

```text
问题 -> 探索 -> 决策 -> 实施 -> 测试 -> 最终结果
```

智能查询默认召回原子 claim；用户询问研发过程时再展开关系链和原始会话。
